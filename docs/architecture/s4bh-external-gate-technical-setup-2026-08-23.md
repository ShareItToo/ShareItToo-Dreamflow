external gates and binds each gate to its current canonical repository

3. Apple membership, iOS signing and physical-device evidence;
4. Firebase owner terms and console controls;
5. PSP contract and eight real sandbox scenarios;
6. Privacy, retention and legal-hold decisions;
7. Store submission and Google closed testing;
8. authentic Economics and cost inputs;
9. exact pilot region, roster and scope; and
10. Walid's separate activation decision.

All ten technical preparations are complete. All ten external readiness states
remain false and contain no external evidence reference. The manifest forbids
personal data, account identifiers, credentials and secrets and records every
live/cost boundary as false. The accompanying runbook reduces the eventual
Walid session to the ordered human/provider decisions and configuration steps,
while preserving each canonical specialist runbook.

The validator cross-checks the manifest against current Legal, Operations,
Device, platform-account, PSP, Privacy, retention, Store, Economics, pilot and
P0B truth. It also rejects unsafe evidence paths and credential-shaped fields.
The ordinary preflight returns:

```json
{"status":"prepared-hold","requiredGateCount":10,"technicallyPreparedGateCount":10,"externallyReadyGateCount":0,"releaseDecision":"hold-no-go"}
```

Strict readiness intentionally fails and names all ten unresolved gates. It
must remain red until authentic external evidence updates the canonical source
first. A login, credential, account setup or prepared worksheet can therefore
never silently become release approval. The Store README was also corrected
to the existing machine state: Google Play account setup is ready, while Apple
membership and Firebase owner terms remain open.
