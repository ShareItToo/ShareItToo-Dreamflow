# WP100 — Pixel Legal Routes Read-Only Closure

## Result

The exact physical `1.0.0+2026091001` Internal/Staging Pixel candidate passed
all seven informational legal routes: Impressum, Datenschutz, AGB,
Community-Regeln, Gebühren & Zahlungsbedingungen, Stornierungsbedingungen and
Haftungsausschluss.

Every route was bound first to the private exact candidate archive, installed
APK, unlocked physical device and a no-post-candidate-mobile-source-drift
check. The legal root was then prepared once and re-verified before each
single-document diagnostic. Each completed document returned to that root;
only an explicit retained-root phase was permitted to leave it available for
the next document. The final document restored the normal app surface.

## Why the runner changed

The historical legal command only knew a current source head, which could
incorrectly imply that the installed direct APK was built from later
documentation or tooling commits. It now accepts a mutually exclusive private
candidate archive path and validates that the application source has not
changed since that archive. The original current-head mode remains supported
for its historical checks.

The phasing preserves full destination markers and failure behavior. It does
not shorten a wait, bypass a legal route, or convert a host command window into
an application dependency. A one-document run stays a subset result and cannot
claim the entire set.

## Boundaries

This is only physical route-reachability evidence. It does **not** say that a
lawyer, operator or owner has approved the documents; that independent legal
gate remains open. It neither opens nor submits a withdrawal flow, support
contact, account action, payment action or Store action. No Staging,
Production, OnePlus or credential state changed.

The focused legal runner suite passed six tests and the full Node tool suite
passed 2,635 tests. The remaining WP100 work is strictly the separately
reversible large-text and light/dark/background evidence.
