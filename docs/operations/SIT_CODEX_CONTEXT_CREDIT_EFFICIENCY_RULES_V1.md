# SIT Codex context and credit efficiency rules V1

Status: binding operating policy for the active autonomous SIT runway

These rules reduce repeated context, token use, CI use and candidate churn
without weakening implementation, security, legal, privacy, data-integrity or
release evidence.

## One active package

- Work on one bounded package at a time and carry forward one compact state
  capsule only: objective, base/final HEAD, candidate identity, changed paths,
  decisive proof, remaining blockers and next package.
- Detailed logs, prior attempts and historical evidence stay in their existing
  files. Do not reload or repeat them unless a concrete discrepancy requires
  it. "Clear old context" never means deleting Git history, audit evidence,
  legal records or user data.
- Select the next package by highest launch-readiness value. Do not reopen a
  closed package without new contradictory evidence or a changed dependency.

## Proportionate verification

- Inspect only the active package inputs and adjacent code/tests. Search first;
  do not reread entire large state files or Drive folders by default.
- Run focused deterministic checks while developing. Run one complete local
  regression on the final package/candidate HEAD and require exact-HEAD GitHub
  Regression and CodeQL before closure.
- Do not repeat an unchanged green gate. Repeat only when its bound source,
  environment, candidate or assertion changed, or when a recorded failure must
  be reproduced.
- Keep normal deterministic timing and parallelism. Rate-limit, cache, timing
  or reduced-parallelism workarounds are Technical Debt, never release proof.

## Compact evidence and communication

- Keep raw command output local. Record only the command/gate identity, result,
  exact HEAD, relevant counts or artifact hashes and a short failure cause.
- Never copy credentials, account identifiers, private links, raw device IDs,
  cookies, tokens, KYC data or secret-bearing configuration into Git, Drive
  reports or chat.
- Notify Walid through the established Maximus/Telegram route only for a truly
  non-delegable owner action. Continue every independent package lane quietly.

## Candidate and source discipline

- Maintain one successor candidate for one accepted source state. Do not create
  additional builds merely to inspect unchanged behavior.
- Reuse verified local dependencies and the scoped Mac-mini build workspace;
  never weaken clean-checkout reproducibility or make a local workaround a
  permanent prerequisite.
- Preserve source-hash ratchets and update them mechanically when a bound source
  changes. A hash refresh cannot change an approval, legal or release claim.
- Drive stores this canonical policy once in the current SIT Codex folder.
  Repository `AGENTS.md`, `docs/current_work_package.md` and
  `docs/current_state.md` point to it instead of duplicating the full policy.

## Boundaries

Efficiency never authorizes Production, public Store rollout, PR merge, live
payment, Cloud/VPS/DNS/Firebase-console/provider mutation, paid purchase or
OnePlus access. Existing named owner and external gates remain fail-closed.
